Code Block

Code people read or copy: an API request, a webhook's payload, a config file, a log excerpt, an embed snippet. A <pre><code> in a frame, with a title and a copy button. Specification: docs/components/code-block.md

Basics

A .canon-code-block around a <pre><code>. A .canon-code-block-header first holds a .canon-code-block-title (a file name, or what the code is) and its buttons: usually a Button with command="--canon-copy", whose commandfor names the <code>. It copies the code's text, without the highlighting.

Without a header

For a short snippet, leave out the header: the copy button goes after the <pre>, and sits in the code's top corner. It is the right corner in every language, where lines end, since code reads left to right.

curl https://api.example.com/v1/invoices/INV-2041 \
  -H "Authorization: Bearer $API_TOKEN"

Highlighting

Canon doesn't highlight code; do it before the page is sent (on the server or at build time) and put the result inside the <code>. Themes color tokens by twinkleplop's names: <span class="tok string">, tok keyword, tok tag_name and so on. Code without tokens is plain text, which suits logs and keys.

These docs use twinkleplop for their own code: the examples on this page were highlighted ahead of time, and the Playground's HTML and the code in these notes are highlighted in the browser with @twinkleplop/html. Any highlighter works, as long as its tokens get those class names.

Long code

Code keeps its lines and scrolls in its box, sideways and, with --canon-code-block-max-height, down. A box that scrolls becomes a region named by the title (or "Code"), so keyboards can reach and scroll it.

deploy.yaml 
# Billing worker, production
service: billing-worker
image: registry.example.com/billing-worker:2.14.0
replicas: 3
resources:
  cpu: 500m
  memory: 512Mi
env:
  - name: QUEUE_URL
    value: amqps://queue.internal:5671/billing
  - name: RETRY_LIMIT
    value: "5"
  - name: LOG_LEVEL
    value: info
healthcheck:
  path: /healthz
  interval: 10s
  timeout: 2s
schedule:
  - cron: "0 3 * * *"
    task: reconcile-payouts
  - cron: "*/15 * * * *"
    task: retry-failed-charges

Wrapping

Long lines scroll by default, so columns stay aligned. A wrap button in the header, before the copy button, lets people wrap them instead: a Button with command="--canon-wrap", named "Wrap lines", whose aria-pressed is the state. Start it pressed (aria-pressed="true") where wrapped reads better, as for logs on a narrow screen.
