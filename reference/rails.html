With Rails

Canon in a Rails app: the asset pipeline and Turbo, a form builder that writes every form in Canon's markup, errors, flash messages as toasts, and lists with pages. For adding Canon to a page, start with Getting started.

Set up

Canon is two files, and the asset pipeline serves them like your own. Take them from the npm package (keep the css folder whole: a stylesheet finds its icons and fonts beside it):

Terminal 
npm i canon-ui
mkdir -p vendor/assets/canon/js
cp -R node_modules/canon-ui/css vendor/assets/canon/
cp node_modules/canon-ui/js/canon.js vendor/assets/canon/js/

Then link them in the layout:

app/views/layouts/application.html.erb 
<%= csrf_meta_tags %>
<%= stylesheet_link_tag "css/canon/canon" %>
<%= javascript_include_tag "js/canon", defer: true %>
<%= javascript_importmap_tags %>

Back and Forward. Turbo shows the copy of the page it kept, with what canon.js had drawn in it. canon.js takes its drawn parts out of the copy and sets up each component again, once, so a Combobox still has one list and a Pagination one row of pages. Turbo's page cache can stay on.

Or link both files from a CDN, as Getting started shows. Either way there's nothing to build and no gem to add.

Every form in Canon's markup

A form builder gives every form_with Canon's markup. First, stop Rails wrapping fields that have errors in a <div class="field_with_errors">: Canon marks them itself, and the wrapper would break a Field's structure.

config/initializers/canon.rb 
# Canon marks invalid fields itself (aria-invalid and a message), so Rails
# shouldn't wrap them in a <div class="field_with_errors">.
ActionView::Base.field_error_proc = ->(html_tag, _instance) { html_tag }

The builder writes each field as its Canon component: a Text Input, Textarea, Select, Date or Password in a Field, a Checkbox, radios in a Fieldset, and errors about the whole record in a danger Alert. It ties the label, description and message to the control (aria-describedby, aria-invalid), adds the empty placeholder Canon's text boxes need, and reads presence validations: those fields are required, the others say "(optional)".

app/form_builders/canon_form_builder.rb 
# Canon's markup for Rails forms: each field as its Canon component, its
# label, description and error message tied to the control.
class CanonFormBuilder < ActionView::Helpers::FormBuilder
  # A Field: label, optional description, the box, and a message.
  #   f.field :email, as: :email_field, hint: "Where the invoice is sent."
  #   f.field :status, as: :select, choices: [["Draft", "draft"], ["Sent", "sent"]]
  def field(method, as: :text_field, label: nil, hint: nil, choices: nil, **options)
    id = field_id(method)
    control = options.merge(control_attributes(method, hint))
    control[:placeholder] ||= "" if %i[text_field email_field url_field telephone_field search_field number_field password_field text_area].include?(as)
    control[:required] = true if required?(method)

    @template.tag.div(class: "canon-field") do
      @template.safe_join([
        @template.tag.div(class: "canon-label") do
          @template.safe_join([
            label(method, class: "canon-label-text") { label_text(method, label, optional: !required?(method)) },
            (@template.tag.p(hint, class: "canon-label-description", id: "#{id}_hint") if hint)
          ].compact)
        end,
        box(as, method, choices, control),
        message(method, "canon-field-message")
      ])
    end
  end

  # A Checkbox: the control, its label after it, and a message. Rails'
  # hidden "0" (so unchecking is sent too) goes before it, outside: a
  # Choice holds only its checkbox, label and message.
  def check(method, label: nil, **options)
    @template.safe_join([
      hidden_field(method, value: "0", id: nil),
      @template.tag.div(class: "canon-choice") do
        @template.safe_join([
          check_box(method, options.merge(control_attributes(method, nil), include_hidden: false)),
          label(method, label, class: "canon-choice-label"),
          message(method, "canon-choice-message")
        ])
      end
    ])
  end

  # Radios in a Fieldset: the legend, an optional hint, one Radio each,
  # and the group's message.
  def radios(method, choices, legend:, hint: nil)
    id = field_id(method)
    described = [("#{id}_hint" if hint), "#{id}_error"].compact.join(" ")
    @template.tag.fieldset(class: "canon-fieldset", aria: { describedby: described }) do
      @template.safe_join([
        @template.tag.legend(legend, class: "canon-fieldset-legend"),
        (@template.tag.p(hint, class: "canon-fieldset-hint", id: "#{id}_hint") if hint),
        *choices.map do |text, value|
          @template.tag.div(class: "canon-choice") do
            @template.safe_join([
              radio_button(method, value, required: required?(method), aria: { invalid: (true if errors?(method)) }),
              label(method, text, value: value, class: "canon-choice-label")
            ])
          end
        end,
        message(method, "canon-fieldset-message")
      ].compact)
    end
  end

  # Errors about the whole record, in a danger Alert.
  def base_errors
    messages = object&.errors&.full_messages_for(:base) || []
    return if messages.empty?
    @template.tag.div(class: "canon-alert", data: { intent: "danger" }, role: "alert") do
      @template.tag.p(messages.join(" "), class: "canon-alert-title")
    end
  end

  private

  def box(as, method, choices, control)
    case as
    when :text_area then @template.tag.div(text_area(method, control), class: "canon-textarea")
    when :select then @template.tag.div(select(method, choices, {}, control), class: "canon-select")
    when :date_field then @template.tag.div(date_field(method, control), class: "canon-date")
    when :password_field
      @template.tag.div(class: "canon-password") do
        @template.safe_join([
          password_field(method, control),
          @template.tag.button(type: "button", class: "canon-button", data: { emphasis: "minimal", display: "icon" },
                               aria: { pressed: false }, commandfor: field_id(method), command: "--canon-toggle-password") do
            @template.safe_join([
              @template.tag.span(class: "canon-icon", data: { icon: "eye" }, aria: { hidden: true }),
              @template.tag.span("Show password", class: "canon-button-label")
            ])
          end
        ])
      end
    else @template.tag.div(public_send(as, method, control), class: "canon-text-input")
    end
  end

  def control_attributes(method, hint)
    id = field_id(method)
    described = [("#{id}_hint" if hint), "#{id}_error"].compact.join(" ")
    { aria: { describedby: described, invalid: (true if errors?(method)) } }
  end

  def message(method, css_class)
    text = object&.errors&.full_messages_for(method)&.join(" ")
    @template.tag.p(text, class: css_class, id: "#{field_id(method)}_error", data: { intent: ("danger" if errors?(method)) })
  end

  def label_text(method, text, optional:)
    text ||= method.to_s.humanize
    return text unless optional
    @template.safe_join([text, " ", @template.tag.span("(optional)", class: "canon-label-optional")])
  end

  def errors?(method) = object&.errors&.include?(method)

  def required?(method)
    object.class.respond_to?(:validators_on) &&
      object.class.validators_on(method).any?(ActiveModel::Validations::PresenceValidator)
  end
end

Make it every form's builder:

app/controllers/application_controller.rb 
class ApplicationController < ActionController::Base
  default_form_builder CanonFormBuilder
end

Using it

Each field is one line, the field's kind in as:. A canon-form spaces them:

app/views/invoices/new.html.erb 
<h1>New invoice</h1>
<%= form_with model: @invoice, url: invoices_path, class: "canon-form", html: { novalidate: true } do |f| %>
  <%= f.base_errors %>
  <%= f.field :customer %>
  <%= f.field :email, as: :email_field, hint: "Where the invoice is sent." %>
  <%= f.field :status, as: :select, choices: [["Draft", "draft"], ["Sent", "sent"], ["Paid", "paid"]] %>
  <%= f.field :due, as: :date_field %>
  <%= f.field :notes, as: :text_area %>
  <%= f.field :portal_password, as: :password_field %>
  <%= f.radios :channel, [["Email", "email"], ["Post", "post"]], legend: "Channel", hint: "How the invoice reaches them." %>
  <%= f.check :reminders, label: "Send reminders when overdue" %>
  <button type="submit" class="canon-button" data-emphasis="high"><span class="canon-button-label">Save</span></button>
<% end %>

Checkboxes keep Rails' hidden 0, so unchecking one is sent too; the builder puts it before the Checkbox, outside it.

Errors

Validations are the errors. With these:

app/models/invoice.rb 
class Invoice < ApplicationRecord
  validates :customer, :email, :channel, :due, presence: true
  validates :email, format: { with: /@/ }, allow_blank: true
  validate { errors.add(:base, "Globex has no payment on record.") if customer == "Globex" && status == "paid" }
end

render the form again with status 422, as Turbo expects of a form with errors:

app/controllers/invoices_controller.rb 
def create
  @invoice = Invoice.new(invoice_params)
  if @invoice.save
    redirect_to invoices_path, notice: "Invoice for #{@invoice.customer} saved."
  else
    render :new, status: :unprocessable_entity
  end
end

Each wrong field comes back marked, with its message, and what people typed. An email field after a failed save:

Rendered 
<div class="canon-field">
  <div class="canon-label">
    <label class="canon-label-text" for="invoice_email">Email</label>
    <p class="canon-label-description" id="invoice_email_hint">Where the invoice is sent.</p>
  </div>
  <div class="canon-text-input"><input aria-describedby="invoice_email_hint invoice_email_error" aria-invalid="true" placeholder="" required="required" type="email" value="nope" name="invoice[email]" id="invoice_email"></div>
  <p class="canon-field-message" id="invoice_email_error" data-intent="danger">Email is invalid</p>
</div>

The browser's own checks (required, type="email") run first unless the form has novalidate, and canon.js shows their messages in the same place.

Flash messages as toasts

A redirect's notice ("Invoice saved") shows as a Toast. The layout writes the flash into the page, hidden:

app/views/layouts/application.html.erb 
<% if flash.any? %>
  <ul class="flash" hidden>
    <% flash.each do |type, message| %>
      <li data-intent="<%= type == "alert" ? "danger" : "success" %>"><%= message %></li>
    <% end %>
  </ul>
<% end %>

and a few lines hand it to canon.js after each visit, Turbo's included:

app/javascript/application.js 
// Flash messages as Canon toasts, on the first load and after each Turbo visit.
addEventListener("turbo:load", () => {
  for (const message of document.querySelectorAll(".flash li")) {
    document.dispatchEvent(new CustomEvent("canon-toast", {
      detail: { intent: message.dataset.intent, title: message.textContent },
    }));
  }
  document.querySelector(".flash")?.remove();
});

A toast needs JavaScript. A message people must read even without it (a save that failed) belongs in the page, as an Alert.

Lists and pages

Rails has no paginator of its own, and a page is a few lines of arithmetic:

app/controllers/invoices_controller.rb 
PER_PAGE = 25

def index
  @pages = [(Invoice.count / PER_PAGE.to_f).ceil, 1].max
  @page = params.fetch(:page, 1).to_i.clamp(1, @pages)
  @invoices = Invoice.order(issued_on: :desc).offset((@page - 1) * PER_PAGE).limit(PER_PAGE)
end

Canon's Pagination shows it. With data-pages and data-page, canon.js draws the page numbers and fits them to the room; the list written inside is what shows without JavaScript: Previous, "Page 4 of 10", Next.

app/views/canon/_pagination.html.erb 
<nav class="canon-pagination" aria-label="Pagination" data-pages="<%= pages %>" data-page="<%= page %>" data-href="?page={page}">
  <ol>
    <li><%= tag.a class: "canon-pagination-prev", href: ("?page=#{page - 1}" if page > 1), rel: ("prev" if page > 1), aria: { disabled: (true if page == 1) } do %>
      <span class="canon-icon" data-icon="chevron-left" aria-hidden="true"></span>
      <span class="canon-pagination-label">Previous</span>
    <% end %></li>
    <li><span class="canon-pagination-current">Page <%= page %> of <%= pages %></span></li>
    <li><%= tag.a class: "canon-pagination-next", href: ("?page=#{page + 1}" if page < pages), rel: ("next" if page < pages), aria: { disabled: (true if page == pages) } do %>
      <span class="canon-pagination-label">Next</span>
      <span class="canon-icon" data-icon="chevron-right" aria-hidden="true"></span>
    <% end %></li>
  </ol>
</nav>
app/views/invoices/index.html.erb 
<table class="canon-table">
  <thead>…</thead>
  <tbody>
    <% @invoices.each do |invoice| %>
      <tr><td><%= invoice.number %></td><td><%= invoice.customer %></td><td data-align="end"><%= invoice.total %></td></tr>
    <% end %>
  </tbody>
</table>
<%= render "canon/pagination", page: @page, pages: @pages %>

If the list's address carries filters too, write them into data-href and the links, so a new page keeps them.

Turbo Frames and Streams

canon.js watches the page, so HTML that a Turbo Frame or Stream puts in is set up when it lands: a Combobox gets its list, a Date its calendar. Render the same partials and the same builder; there's nothing to call. For pages that htmx updates instead, see With htmx.
