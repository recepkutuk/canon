With Django

Canon in a Django app: static files, every form rendered as Canon's Fields, errors, messages as toasts, and lists with pages. For adding Canon to a page, start with Getting started.

Set up

Canon is two files, so they go with your static files. Take them from the npm package (keep the css folder whole: a stylesheet finds its icons and fonts beside it):

Terminal 
npm i canon-ui
mkdir -p static/canon/js
cp -R node_modules/canon-ui/css static/canon/
cp node_modules/canon-ui/js/canon.js static/canon/js/

Then link them in your base template:

templates/base.html 
{% load static %}
<link rel="stylesheet" href="{% static 'canon/css/canon/canon.css' %}">
<script src="{% static 'canon/js/canon.js' %}" defer></script>

Or link both from a CDN, as Getting started shows. Either way there's nothing to build and nothing to add to INSTALLED_APPS for Canon itself.

Every form in Canon's markup

Django renders forms through templates, so one form renderer gives every form Canon's markup: {{ form }} comes out as Canon's Fields, with nothing to change in your forms. It takes Django 5.2 or later.

The renderer names two templates and adds the one attribute Django doesn't write: a Field's text boxes carry a placeholder, even an empty one, so themes can tell when a box is empty.

myapp/renderers.py 
from django.forms import BoundField
from django.forms.renderers import TemplatesSetting


class CanonBoundField(BoundField):
    def build_widget_attrs(self, attrs, widget=None):
        attrs = super().build_widget_attrs(attrs, widget)
        widget = widget or self.field.widget
        if getattr(widget, "input_type", None) in {"text", "email", "url", "tel", "search", "number", "password"} or self.widget_type == "textarea":
            attrs.setdefault("placeholder", "")
        return attrs


class CanonRenderer(TemplatesSetting):
    form_template_name = "canon/form.html"
    field_template_name = "canon/field.html"
    bound_field_class = CanonBoundField
settings.py 
INSTALLED_APPS = [
    # …
    "django.forms",
]

FORM_RENDERER = "myapp.renderers.CanonRenderer"

The field template writes each kind of field as its Canon component: a Text Input, Textarea, Select, Date or Password in a Field; a checkbox as a Checkbox; radios and checkbox groups as a Fieldset. Django already puts aria-invalid and aria-describedby on the control, pointing at id_<name>_helptext and id_<name>_error, so the description and the message take those ids.

templates/canon/field.html 
{% if field.use_fieldset %}
<fieldset class="canon-fieldset"{% if field.aria_describedby %} aria-describedby="{{ field.aria_describedby }}"{% endif %}>
  <legend class="canon-fieldset-legend">{{ field.label }}</legend>
  {% if field.help_text %}<p class="canon-fieldset-hint" id="{{ field.auto_id }}_helptext">{{ field.help_text }}</p>{% endif %}
  {% for option in field %}
  <div class="canon-choice">
    {{ option.tag }}
    <label class="canon-choice-label" for="{{ option.id_for_label }}">{{ option.choice_label }}</label>
  </div>
  {% endfor %}
  <p class="canon-fieldset-message" id="{{ field.auto_id }}_error"{% if field.errors %} data-intent="danger"{% endif %}>{{ field.errors|join:" " }}</p>
</fieldset>
{% elif field.widget_type == "checkbox" %}
<div class="canon-choice">
  {{ field }}
  <label class="canon-choice-label" for="{{ field.id_for_label }}">{{ field.label }}</label>
  <p class="canon-choice-message" id="{{ field.auto_id }}_error"{% if field.errors %} data-intent="danger"{% endif %}>{{ field.errors|join:" " }}</p>
</div>
{% else %}
<div class="canon-field">
  <div class="canon-label">
    <label class="canon-label-text" for="{{ field.id_for_label }}">{{ field.label }}{% if not field.field.required %} <span class="canon-label-optional">(optional)</span>{% endif %}</label>
    {% if field.help_text %}<p class="canon-label-description" id="{{ field.auto_id }}_helptext">{{ field.help_text }}</p>{% endif %}
  </div>
  {% if field.widget_type == "textarea" %}
  <div class="canon-textarea">{{ field }}</div>
  {% elif field.widget_type == "select" or field.widget_type == "selectmultiple" %}
  <div class="canon-select">{{ field }}</div>
  {% elif field.widget_type == "date" %}
  <div class="canon-date">{{ field }}</div>
  {% elif field.widget_type == "password" %}
  <div class="canon-password">
    {{ field }}
    <button type="button" class="canon-button" data-emphasis="minimal" data-display="icon" aria-pressed="false" commandfor="{{ field.id_for_label }}" command="--canon-toggle-password">
      <span class="canon-icon" data-icon="eye" aria-hidden="true"></span>
      <span class="canon-button-label">Show password</span>
    </button>
  </div>
  {% else %}
  <div class="canon-text-input">{{ field }}</div>
  {% endif %}
  <p class="canon-field-message" id="{{ field.auto_id }}_error"{% if field.errors %} data-intent="danger"{% endif %}>{{ field.errors|join:" " }}</p>
</div>
{% endif %}

The form template puts errors about the whole form in a danger Alert at the top, then the fields:

templates/canon/form.html 
{% if form.non_field_errors %}
<div class="canon-alert" data-intent="danger" role="alert">
  <p class="canon-alert-title">{{ form.non_field_errors|join:" " }}</p>
</div>
{% endif %}
{% for field in form.hidden_fields %}{{ field }}{% endfor %}
{% for field in form.visible_fields %}{{ field.as_field_group }}{% endfor %}

Using it

Write the form as always. A canon-form spaces its fields:

templates/invoices/edit.html 
<form class="canon-form" method="post">
  {% csrf_token %}
  {{ form }}
  <button type="submit" class="canon-button" data-emphasis="high">
    <span class="canon-button-label">Save</span>
  </button>
</form>

To arrange fields yourself, render them one at a time. A Form Layout row puts two side by side:

Template 
<div class="canon-form-row">
  {{ form.first_name.as_field_group }}
  {{ form.last_name.as_field_group }}
</div>

Django's DateInput is a text box by default. Give it type="date" and it becomes a Canon Date, with its calendar:

forms.py 
due = forms.DateField(widget=forms.DateInput(attrs={"type": "date"}))

Errors

A form sent back with errors needs nothing more: Django marks each wrong control, and the field template shows its message as a danger one. An email field after a failed submit:

Rendered 
<div class="canon-field">
  <div class="canon-label">
    <label class="canon-label-text" for="id_email">Email</label>
    <p class="canon-label-description" id="id_email_helptext">Where the invoice is sent.</p>
  </div>
  <div class="canon-text-input"><input type="email" name="email" value="nope" maxlength="320" required aria-invalid="true" aria-describedby="id_email_helptext id_email_error" placeholder="" id="id_email"></div>
  <p class="canon-field-message" id="id_email_error" data-intent="danger">Enter a valid email address.</p>
</div>

What people typed comes back in the form, so nothing is lost. The browser's own checks (required, type="email") still run first, and canon.js shows their messages in the same place, so most mistakes are caught before the form is sent.

Messages as toasts

Django's messages framework says what happened after a redirect ("Invoice saved"). Canon shows that as a Toast. First, name the levels as Canon's intents:

settings.py 
from django.contrib import messages

MESSAGE_TAGS = {messages.ERROR: "danger", messages.DEBUG: "info"}

Then, at the end of the base template, hand each message to canon.js:

templates/base.html 
{% if messages %}
<ul id="messages" hidden>
  {% for message in messages %}<li data-intent="{{ message.level_tag }}">{{ message }}</li>{% endfor %}
</ul>
<script>
  addEventListener("DOMContentLoaded", () => {
    for (const message of document.querySelectorAll("#messages li")) {
      document.dispatchEvent(new CustomEvent("canon-toast", {
        detail: { intent: message.dataset.intent, title: message.textContent },
      }));
    }
  });
</script>
{% endif %}

A toast needs JavaScript. A message people must read even without it (a save that failed) belongs in the page, as an Alert.

Lists and pages

Django's Paginator gives the page; Canon's Pagination shows it. With data-pages and data-page, canon.js draws the page numbers and fits them to the room. The list written inside is what shows without JavaScript: Previous, "Page 4 of 10", Next.

templates/canon/pagination.html 
<nav class="canon-pagination" aria-label="Pagination"
     data-pages="{{ page_obj.paginator.num_pages }}" data-page="{{ page_obj.number }}" data-href="?page={page}">
  <ol>
    <li>{% if page_obj.has_previous %}<a class="canon-pagination-prev" href="?page={{ page_obj.previous_page_number }}" rel="prev">{% else %}<a class="canon-pagination-prev" aria-disabled="true">{% endif %}
      <span class="canon-icon" data-icon="chevron-left" aria-hidden="true"></span>
      <span class="canon-pagination-label">Previous</span>
    </a></li>
    <li><span class="canon-pagination-current">Page {{ page_obj.number }} of {{ page_obj.paginator.num_pages }}</span></li>
    <li>{% if page_obj.has_next %}<a class="canon-pagination-next" href="?page={{ page_obj.next_page_number }}" rel="next">{% else %}<a class="canon-pagination-next" aria-disabled="true">{% endif %}
      <span class="canon-pagination-label">Next</span>
      <span class="canon-icon" data-icon="chevron-right" aria-hidden="true"></span>
    </a></li>
  </ol>
</nav>
views.py 
from django.core.paginator import Paginator

def invoice_list(request):
    page_obj = Paginator(Invoice.objects.order_by("-issued"), 25).get_page(request.GET.get("page"))
    return render(request, "invoices/list.html", {"page_obj": page_obj})
templates/invoices/list.html 
<table class="canon-table">
  <thead>…</thead>
  <tbody>
    {% for invoice in page_obj %}
    <tr><td>{{ invoice.number }}</td><td>{{ invoice.customer }}</td><td data-align="end">{{ invoice.total }}</td></tr>
    {% endfor %}
  </tbody>
</table>
{% include "canon/pagination.html" %}

data-href is the pattern for every page's link. If the list's address carries filters too, write them into it, so a new page keeps them.

With htmx

Django and htmx are a common pair. Everything on With htmx applies; Django adds one thing, its CSRF token on every request htmx sends:

templates/base.html 
<body hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'>

Partials are the same templates: a view that answers htmx renders canon/field.html, a form or a table on its own, and canon.js sets it up when it lands.
