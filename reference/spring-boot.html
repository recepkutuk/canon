With Spring Boot

Canon in a Spring Boot app: its files in static/, Thymeleaf fragments or jte templates for every form part, errors from Bean Validation, flash attributes as toasts, and Spring Data pages drawn as Canon's Pagination. For adding Canon to a page, start with Getting started.

Set up

Canon is two files, and Spring Boot serves src/main/resources/static/ as it is. Take them from the npm package (keep the css folder whole: a stylesheet finds its icons and fonts beside it):

Terminal 
npm i canon-ui
mkdir -p src/main/resources/static/canon/js
cp -R node_modules/canon-ui/css src/main/resources/static/canon/
cp node_modules/canon-ui/js/canon.js src/main/resources/static/canon/js/

The layouts below link them as /canon/css/canon/canon.css and /canon/js/canon.js. Or link both from a CDN, as Getting started shows. Either way there's nothing to build and no dependency to add.

The controller

Thymeleaf and jte share everything on the Java side. A form object with Bean Validation (spring-boot-starter-validation):

src/main/java/com/example/InvoiceForm.java 
public class InvoiceForm {

    @NotBlank
    private String customer;

    @NotBlank
    @Email
    private String email;

    private String status = "draft";

    @NotNull
    @DateTimeFormat(iso = DateTimeFormat.ISO.DATE)
    private LocalDate due;

    private String notes;

    private String portalPassword;

    @NotBlank
    private String channel;

    private boolean reminders;

    // getters and setters, and toInvoice()
}

A select's or radios' choices are a list of Options, in the order they show:

src/main/java/com/example/Option.java 
public record Option(String value, String label) {
}

@Valid checks the form; with errors, the controller shows the form again with what was typed, and otherwise redirects with a flash attribute:

src/main/java/com/example/InvoiceController.java 
@Controller
@RequestMapping("/invoices")
public class InvoiceController {

    private final InvoiceRepository invoices;

    public InvoiceController(InvoiceRepository invoices) {
        this.invoices = invoices;
    }

    @ModelAttribute("statuses")
    List<Option> statuses() {
        return List.of(new Option("draft", "Draft"), new Option("sent", "Sent"), new Option("paid", "Paid"));
    }

    @ModelAttribute("channels")
    List<Option> channels() {
        return List.of(new Option("email", "Email"), new Option("post", "Post"));
    }

    @GetMapping
    String index(@PageableDefault(size = 25, sort = "issuedOn", direction = Sort.Direction.DESC) Pageable pageable, Model model) {
        model.addAttribute("invoices", invoices.findAll(pageable));
        return "invoices/index";
    }

    @GetMapping("/new")
    String create(Model model) {
        model.addAttribute("invoice", new InvoiceForm());
        return "invoices/create";
    }

    @PostMapping
    String store(@Valid @ModelAttribute("invoice") InvoiceForm invoice, BindingResult result, RedirectAttributes redirect) {
        if (result.hasErrors()) {
            return "invoices/create";
        }

        invoices.save(invoice.toInvoice());

        redirect.addFlashAttribute("status", "Invoice for " + invoice.getCustomer() + " saved.");
        return "redirect:/invoices";
    }
}

Canon's Pagination counts pages from 1, so Spring Data does too:

src/main/resources/application.properties 
spring.data.web.pageable.one-indexed-parameters=true

A page's links keep the list's filters: PageLinks writes this request's address with another page in it, or with {page}, the pattern canon.js fills in. Thymeleaf templates call it as a bean (@pageLinks); jte templates make their own:

src/main/java/com/example/PageLinks.java 
@Component
public class PageLinks {

    /** This request's address with another page. */
    public String href(int page) {
        return withPage(String.valueOf(page));
    }

    /** This request's address with {page} for the page: Pagination's data-href. */
    public String pattern() {
        return withPage("{page}");
    }

    private static String withPage(String page) {
        return "?" + ServletUriComponentsBuilder.fromCurrentRequest()
                .replaceQueryParam("page", page)
                .build()
                .getQuery();
    }
}

Fields as fragments

Three fragments write Canon's form parts. They're called with named parameters, so each one leaves out what it doesn't need. A field binds to the form's th:object with th:field, which writes its name and value (what was typed, after a failed save) and marks the selected option; #fields finds its errors:

src/main/resources/templates/canon.html 
<!--/* A Field: name and label; type, hint, options, required and id if needed. */-->
<div class="canon-field" th:fragment="field"
     th:with="id=${id ?: name}, type=${type ?: 'text'}, error=${#fields.hasErrors(name)},
              describedBy=${(hint != null ? id + '-hint ' : '') + id + '-error'}">
    <div class="canon-label">
        <label class="canon-label-text" th:for="${id}">[[${label}]]<th:block th:unless="${required}"> <span class="canon-label-optional">(optional)</span></th:block></label>
        <p class="canon-label-description" th:if="${hint}" th:id="${id + '-hint'}" th:text="${hint}"></p>
    </div>
    <th:block th:switch="${type}">
        <div class="canon-textarea" th:case="'textarea'">
            <textarea th:id="${id}" th:field="*{__${name}__}" placeholder th:required="${required}" th:aria-describedby="${describedBy}" th:aria-invalid="${error} ? 'true'"></textarea>
        </div>
        <div class="canon-select" th:case="'select'">
            <select th:id="${id}" th:field="*{__${name}__}" th:required="${required}" th:aria-describedby="${describedBy}" th:aria-invalid="${error} ? 'true'">
                <option th:each="option : ${options}" th:value="${option.value()}" th:text="${option.label()}"></option>
            </select>
        </div>
        <div class="canon-date" th:case="'date'">
            <input type="date" th:id="${id}" th:field="*{__${name}__}" th:required="${required}" th:aria-describedby="${describedBy}" th:aria-invalid="${error} ? 'true'">
        </div>
        <div class="canon-password" th:case="'password'">
            <input type="password" th:id="${id}" th:field="*{__${name}__}" placeholder th:required="${required}" th:aria-describedby="${describedBy}" th:aria-invalid="${error} ? 'true'">
            <button type="button" class="canon-button" data-emphasis="minimal" data-display="icon" aria-pressed="false" th:commandfor="${id}" command="--canon-toggle-password">
                <span class="canon-icon" data-icon="eye" aria-hidden="true"></span>
                <span class="canon-button-label">Show password</span>
            </button>
        </div>
        <div class="canon-text-input" th:case="*">
            <input th:type="${type}" th:id="${id}" th:field="*{__${name}__}" placeholder th:required="${required}" th:aria-describedby="${describedBy}" th:aria-invalid="${error} ? 'true'">
        </div>
    </th:block>
    <p class="canon-field-message" th:id="${id + '-error'}" th:data-intent="${error} ? 'danger'" th:text="${#strings.listJoin(#fields.errors(name), ' ')}"></p>
</div>

It writes a Text Input, Textarea, Select, Date or Password in a Field, ties the description and message to the control (aria-describedby, aria-invalid), adds the empty placeholder Canon's text boxes need, and says "(optional)" unless the field is required.     <div class="canon-choice" th:each="option : ${options}">

        <label class="canon-choice-label" th:for="${name + '-' + option.value()}" th:text="${option.label()}"></label>
    </div>
    <p class="canon-fieldset-message" th:id="${name + '-error'}" th:data-intent="${error} ? 'danger'" th:text="${#strings.listJoin(#fields.errors(name), ' ')}"></p>
</fieldset>

th:field adds a hidden _reminders input after a checkbox, so an unchecked box binds as false; Canon's Checkbox doesn't mind it.

        addEventListener("DOMContentLoaded", () => {
            const status = document.getElementById("status");
            document.dispatchEvent(new CustomEvent("canon-toast", {

One fragment draws a Spring Data Page as Canon's Pagination. It calls PageLinks in th:with: Thymeleaf 3.1 doesn't let th:href or th:data-* call a bean:

src/main/resources/templates/canon.html 
<!--/* Pagination for a Spring Data Page. */-->
<nav class="canon-pagination" aria-label="Pagination" th:fragment="pagination(page)"
     th:with="current=${page.number + 1}, pages=${page.totalPages > 0 ? page.totalPages : 1},
              pattern=${@pageLinks.pattern()},
              previous=${page.hasPrevious() ? @pageLinks.href(current - 1) : null},
              next=${page.hasNext() ? @pageLinks.href(current + 1) : null}"
     th:data-pages="${pages}" th:data-page="${current}" th:data-href="${pattern}">
    <ol>
        <li>
            <a class="canon-pagination-prev" th:attr="href=${previous}" th:rel="${previous} ? 'prev'" th:aria-disabled="${previous} ? null : 'true'">

                <span class="canon-pagination-label">Previous</span>
            </a>

        <li>

Fields as templates

jte has no form binding, so its templates read the form's BindingResult: getFieldValue() is what was typed after a failed save (or the form's own value), and getFieldError() its error. A template names what it takes, and the BindingResult's name in the model isn't one it can, so the controller hands it over as form:

src/main/java/com/example/InvoiceController.java 
@GetMapping("/new")
String create(Model model) {
    model.addAttribute("form", new BeanPropertyBindingResult(new InvoiceForm(), "invoice"));
    return "invoices/create";
}

@PostMapping
String store(@Valid @ModelAttribute("invoice") InvoiceForm invoice, BindingResult result, Model model, RedirectAttributes redirect) {
    if (result.hasErrors()) {
        model.addAttribute("form", result);
        return "invoices/create";
    }

    // as above
}

Three templates write Canon's form parts, with the same markup as Thymeleaf's fragments. Parameters with a default can be left out:

src/main/jte/canon/field.jte 
@import java.util.List
@import org.springframework.validation.Errors
@import org.springframework.validation.FieldError
@import com.example.Option

@param Errors form
@param String name
@param String label
@param String type = "text"
@param String hint = null
@param List<Option> options = List.of()
@param boolean required = false
@param String id = null

!{String fieldId = id != null ? id : name;}
!{FieldError error = form.getFieldError(name);}
!{Object value = form.getFieldValue(name);}
!{String current = value != null ? value.toString() : null;}
!{String describedBy = (hint != null ? fieldId + "-hint " : "") + fieldId + "-error";}
!{String invalid = error != null ? "true" : null;}
<div class="canon-field">
    <div class="canon-label">
        <label class="canon-label-text" for="${fieldId}">${label}@if(!required) <span class="canon-label-optional">(optional)</span>@endif</label>
        @if(hint != null)
            <p class="canon-label-description" id="${fieldId}-hint">${hint}</p>
        @endif
    </div>
    @if(type.equals("textarea"))
        <div class="canon-textarea">
            <textarea id="${fieldId}" name="${name}" placeholder required="${required}" aria-describedby="${describedBy}" aria-invalid="${invalid}">${current}</textarea>
        </div>
    @elseif(type.equals("select"))
        <div class="canon-select">
            <select id="${fieldId}" name="${name}" required="${required}" aria-describedby="${describedBy}" aria-invalid="${invalid}">
                @for(var option : options)
                    <option value="${option.value()}" selected="${option.value().equals(current)}">${option.label()}</option>
                @endfor
            </select>
        </div>
    @elseif(type.equals("date"))
        <div class="canon-date">
            <input type="date" id="${fieldId}" name="${name}" value="${current}" required="${required}" aria-describedby="${describedBy}" aria-invalid="${invalid}">
        </div>
    @elseif(type.equals("password"))
        <div class="canon-password">
            <input type="password" id="${fieldId}" name="${name}" placeholder required="${required}" aria-describedby="${describedBy}" aria-invalid="${invalid}">
            <button type="button" class="canon-button" data-emphasis="minimal" data-display="icon" aria-pressed="false" commandfor="${fieldId}" command="--canon-toggle-password">
                <span class="canon-icon" data-icon="eye" aria-hidden="true"></span>
                <span class="canon-button-label">Show password</span>
            </button>
        </div>
    @else
        <div class="canon-text-input">
            <input type="${type}" id="${fieldId}" name="${name}" value="${current}" placeholder required="${required}" aria-describedby="${describedBy}" aria-invalid="${invalid}">
        </div>
    @endif
    <p class="canon-field-message" id="${fieldId}-error" data-intent="${error != null ? "danger" : null}">${error != null ? error.getDefaultMessage() : null}</p>
</div>

    private Csrf() {
    }

    /** Spring Security's CSRF token for this request. */
    public static CsrfToken token() {
        var request = ((ServletRequestAttributes) RequestContextHolder.currentRequestAttributes()).getRequest();
        return (CsrfToken) request.getAttribute(CsrfToken.class.getName());
    }

        <p class="canon-label-description" id="email-hint">Where the invoice is sent.</p>
    </div>
    <div class="canon-text-input">
        <input type="email" id="email" name="email" value="nope" placeholder required aria-describedby="email-hint email-error" aria-invalid="true">
    </div>
    <p class="canon-field-message" id="email-error" data-intent="danger">must be a well-formed email address</p>
</div>

The browser's own checks (required, type="email") run first unless the form has novalidate, and canon.js shows their messages in the same place. A toast needs JavaScript: a message people must read even without it (a save that failed) belongs in the page, as an Alert.

With htmx

Everything on With htmx applies. With Thymeleaf, htmx-spring-boot's dialect adds Spring Security's CSRF token to every hx:post, hx:put, hx:patch and hx:delete:

src/main/resources/templates/invoices/index.html 
<button type="button" class="canon-button" hx:delete="@{/invoices/{id}(id=${invoice.id})}" hx-target="closest tr" hx-swap="outerHTML">
    <span class="canon-button-label">Delete</span>
</button>

With jte, the layout sends the token with every request htmx makes:

src/main/jte/layout.jte 
@import com.example.Csrf
…
!{var csrf = Csrf.token();}
<body hx-headers='{"${csrf.getHeaderName()}": "${csrf.getToken()}"}'>

Partials are the same templates: a handler that answers htmx renders a field, a form or a table on its own (with Thymeleaf, a fragment: "invoices/index :: list"), and canon.js sets it up when it lands.
